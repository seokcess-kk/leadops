# 골드셋 라벨링 기준 (설계서 9.1 · Phase 0)

n=120 (업종당 30). 라벨링이 끝나면 `pnpm spike measure` 가 M1~M14 를 계산하고
Phase 0 판정(`stop` / `inconclusive`)을 낸다.

> **이 문서가 채점 기준의 유일한 출처다.** 열 이름에 기준을 담지 않은 이유가 이것이다 —
> 기준이 두 곳에 있으면 라벨러마다 다르게 읽고, 그 편차가 지표 편차로 나타난다.

---

## 0. 시작 전에

```bash
# 1) 표본 추출 — 실키가 필요하다 (mock 표본으로는 아무것도 측정되지 않는다)
FEATURE_SOURCE=live pnpm spike sample --per-industry 30 --seed 42

# 2) 같은 표본으로 파이프라인을 돌린다 (측정은 '실제로 나온 판정' 을 읽는다)
pnpm worker run --industry=derm,plastic,dental,franchise

# 3) out/sample-seed42.csv 의 label_* 열을 채운다  ← 이 문서

# 4) 측정
pnpm spike measure --goldset out/sample-seed42.csv
```

> ⚠️ **mock 으로는 측정할 수 없다.** mock 어댑터의 홈페이지 도메인은 실재하지 않아
> 사람이 볼 페이지가 없다. `pnpm spike sample` 이 mock 모드면 경고를 낸다.

**소요 시간**: 업체당 5~8분(검색·페이지 확인 포함) × 120 = **10~16시간**. 설계서가 Phase 0 을
10일로 잡은 이유가 이 라벨링이다.

---

## 1. 원칙

**모르면 비워 둔다.** 추측해서 채우면 그 추측이 지표가 되고, 그 지표로 배점을 정한다.
`pnpm spike measure` 는 빈 라벨을 **미측정**으로 보고하고 숫자를 만들지 않는다 —
빈 칸이 `no` 로 읽히는 일은 없다.

**두 사람이 겹쳐 라벨링한다** (최소 20건). 불일치율이 10% 를 넘으면 기준을 다시 맞춘다.
한 사람의 판단 편차가 M2 정밀도에 그대로 실린다.

**시스템 출력을 보지 않고 라벨링한다.** `homepage_url_hint` 는 공공 API 가 준 값이라
참고해도 되지만, 우리 파이프라인이 무엇을 골랐는지는 보지 않는다 — 보면 우리 판정을
검증하는 것이 아니라 우리 판정에 동의하는 것이 된다.

---

## 2. 열별 기준

### `label_official_url`

사람이 찾은 **그 업체의 공식 홈페이지** URL. 없으면 비워 둔다.

찾는 방법: 네이버·구글에 `상호 + 지역` 으로 검색 → 상위 결과 확인.
`homepage_url_hint` 가 있으면 먼저 열어 본다.

### `label_official_status` — M2 (정밀도 ≥0.90 / 재현율 ≥0.75)

| 값 | 의미 |
|---|---|
| `official` | 그 업체가 **직접 운영하는** 사이트를 찾았다 |
| `not_official` | 사이트는 있지만 그 업체 것이 **아니다** (아래 참고) |
| `none` | 공식 홈페이지가 **없다** (플레이스·블로그만 있다) |
| (빈값) | 확인하지 못했다 |

**`official` 로 보는 것**: 자체 도메인 · 임대형 빌더(`modoo.at` 등)로 만든 자체 사이트 ·
서브도메인. **핵심은 그 업체가 내용을 통제하는가**다.

**`not_official` 로 보는 것**:
- 애그리게이터·포털 (`모두닥`, `굿닥`, `강남언니`, `카카오맵`)
- 그 업체 소개만 있는 남의 블로그·카페 글
- 프랜차이즈 **본사** 사이트 (개별 지점을 라벨링하는 경우)
- 병원 네트워크의 **본원** 사이트 (지점 페이지가 따로 없을 때)

**`none` vs 빈값의 차이가 중요하다.** `none` 은 "없다는 것을 확인했다" 이고 빈값은
"확인하지 못했다" 다. `none` 은 M1 분모에 들어가고 빈값은 빠진다.

> ⚠️ **국내 ISP 의 NXDOMAIN 하이재킹**: 존재하지 않는 도메인이 ISP 안내 페이지로
> 응답한다. 열었을 때 통신사 안내·도메인 판매 페이지가 나오면 `none` 이다 (`not_official`
> 이 아니다 — 사이트가 존재하지 않는다).

### `label_has_business_email` — M3b (**stop 게이트**)

홈페이지 **전체**를 봤을 때 **업무용** 이메일이 있었나. `yes` / `no`

- 대표·문의·제휴·담당자 주소는 `yes`
- 개인 이메일로만 보이는 주소는 `no`
- 이미지로만 표기된 주소, `골뱅이`·`[at]` 로 우회 표기된 주소도 **`yes`**
  (사람이 읽어 옮길 수 있으면 있는 것이다)

**어디를 보는가**: 첫 화면 · 하단 푸터(사업자정보) · 문의/오시는 길 · 소개 · 제휴/채용 ·
개인정보처리방침. 6곳을 보고 없으면 `no` 다.

> ❗ **이 열이 프로젝트 중단 게이트다.** M3b < 20% 면 `stop` — export 가능 리드가 0 에
> 수렴하므로 outbound 목적 자체를 재협상한다 (설계서 1550행). 추측해서 채우지 않는다.

### `label_email_location` — M3 (적중률 ≥50%)

그 이메일을 **찾은 페이지의 경로**. 예: `/contact`, `/about`, `/privacy`
전체 URL 로 적어도 된다 (측정 시 경로만 대조한다).

여러 곳에 있으면 **가장 먼저 눈에 띈 곳** 하나만 적는다.
`label_has_business_email = no` 면 비워 둔다.

### `label_email_is_free_mail` — M14 (실측)

그 주소가 무료메일인가. `yes` / `no`
(`gmail.com` · `naver.com` · `daum.net` · `hanmail.net` · `nate.com` 등)

### `label_perceived_exposure` — M7 (**stop 게이트**)

네이버에 `지역 + 업종` (예: `강남 피부과`)으로 검색했을 때 **그 업체가 얼마나 보이는가**.

| 점수 | 기준 |
|---|---|
| 5 | 첫 화면에 여러 번 (플레이스 상위 + 블로그·카페 다수) |
| 4 | 첫 화면에 확실히 보인다 |
| 3 | 스크롤하면 보인다 |
| 2 | 한참 찾아야 하나 나온다 |
| 1 | 상호로 직접 검색하지 않으면 안 보인다 |

**상호로 검색하지 않는다.** 상호로 검색하면 당연히 나온다 — 재려는 것은
**비브랜드 검색에서의 노출**이다.

> ❗ 이 점수와 ORS 의 상관(Spearman ρ)이 M7 이고, **CI 상한 < 0.4 면 `stop`** 이다.
> ORS 가 제품 배점의 25점을 지탱하므로, 상관이 없으면 그 배점의 근거가 없다.

### `label_competitor_validity` — M8 (평균 ≥3.5)

시스템이 고른 경쟁사 3곳이 **타당한가** 1~5.
검수 화면(`/today` 상세 드로어)의 경쟁사 목록을 보고 판단한다.

| 점수 | 기준 |
|---|---|
| 5 | 셋 다 실제 경쟁 관계 (같은 상권·같은 진료과목·비슷한 규모) |
| 3 | 하나가 어긋난다 |
| 1 | 셋 다 경쟁사가 아니다 (지역·업종·규모가 다르다) |

여기서만 시스템 출력을 본다 — 이 지표는 정의상 시스템의 선정을 평가한다.

### `label_worth_pitching` — M9 (≥60%)

**영업할 만한가.** `yes` / `no`

"이 업체에 마케팅 대행을 제안하면 성사 가능성이 있겠다" 는 영업 담당자의 판단이다.
점수·취약점을 보지 말고 **업체 자체를 보고** 판단한다.

`no` 인 전형: 이미 마케팅이 아주 잘 되어 있다 · 너무 작아서 예산이 없어 보인다 ·
폐업 직전으로 보인다 · 대형 네트워크라 본사가 결정한다.

### `label_render_mode` — M13 (실측)

| 값 | 의미 |
|---|---|
| `ssr` | JS 없이도 내용이 보인다 |
| `js_only` | JS 를 꺼면 빈 화면이다 |
| `blocked` | Cloudflare 등이 접근을 막는다 |

확인: 브라우저 개발자도구 → 설정 → JavaScript 비활성 → 새로고침.
번거로우면 비워 둔다 (실측 지표라 기준이 없다).

### `label_notes`

판단이 애매했던 이유, 특이 사례. **불일치를 조정할 때 이 열만 읽는다.**

## 3. 측정과 판정

```bash
pnpm spike measure --goldset out/sample-seed42.csv
```

- 비율은 **점추정 + Wilson 95% CI**. 가설검정을 하지 않는다 (설계서 9.1)
- 판정은 **`stop` 또는 `inconclusive` 뿐**이다. `go` 는 없다 (R2-06)
- 게이트 입력(M3b·M7)이 없으면 `미판정` 이다 — 라벨을 덜 채운 것이 "진행 허용" 으로
  바뀌지 않는다
- 종료 코드: `inconclusive` = 0, `stop`·`미판정` = 1

**중단 게이트**

| 조건 | 결과 |
|---|---|
| M3b < 20% | `stop` — 이메일 공개율이 낮아 export 가능 리드가 0 에 수렴 |
| M7 CI 상한 < 0.4 | `stop` — ORS 가 체감 노출을 설명하지 못함 → ORS 배점 영구 0 |

`inconclusive` 는 Phase 1 진행 허용이다. **SLA·배점은 확정하지 않는다** — `targets.final_max`
와 ORS 배점은 Phase 4 확증 검증(n=240) 이후에 정한다.

> ⚠️ **M7 은 `FEATURE_ORS=off` 에서 측정할 수 없다.** ORS 를 산출하지 않으므로
> `search_aggregates` 에 점유율이 없다. 현재 하네스는 유효 경쟁사 수를 대리값으로 쓰고
> **주의 표시를 붙여 판정에서 제외한다.** M7 을 실제로 재려면 `FEATURE_ORS=shadow` 로
> 켜야 하고, 그러려면 `source_registry` 승인과 네이버 자격증명이 먼저 필요하다
> (`docs/06-adapter-verification.md`).

## 4. 지금 막혀 있는 것

| 필요한 것 | 없으면 |
|---|---|
| **공공데이터포털 키** (`DATA_GO_KR_SERVICE_KEY`) | 실표본을 뽑을 수 없다 → 측정 불가 |
| **사람의 라벨링 10~16시간** | 지표가 전부 `미측정` |
| **네이버 자격증명 + `FEATURE_ORS=shadow`** | M7(stop 게이트)을 재지 못한다 |

앞의 둘이 없으면 어떤 숫자도 나오지 않는다. 하네스는 그 사실을 **숨기지 않고 `미판정`으로
보고**한다 — 라벨이 없는데 그럴듯한 숫자가 나오는 것이 가장 위험하다.
